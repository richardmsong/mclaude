## Gaps Found

### GAP 1: `mclaude-control-plane` Secret still required by Helm but spec says "no longer a pre-requisite"

| Field | Value |
|-------|-------|
| **Summary** | The `mclaude-cp` Helm chart still requires an externally-created `mclaude-control-plane` Secret (with key `admin-token`) for the `ADMIN_TOKEN` env var, but spec-helm.md states `mclaude-control-plane` is "no longer a pre-requisite." |
| **Code** | `charts/mclaude-cp/templates/control-plane-deployment.yaml` — env entry: `ADMIN_TOKEN` → `secretKeyRef.name: {{ .Values.controlPlane.existingSecret }}` (defaults to `mclaude-control-plane` in `values.yaml`). |
| **Spec** | `docs/charts-mclaude/spec-helm.md` § "Pre-requisite Secrets" — states: "`mclaude-control-plane` is **no longer** a pre-requisite — the operator keys it carried are now generated by the in-chart `init-keys` Job and stored in `mclaude-system/operator-keys`." |
| **Detail** | The operator keys were indeed moved to `mclaude-system/operator-keys` (init-keys Job). However, the `mclaude-control-plane` Secret is still required for the `admin-token` key. Without it, the control-plane pod fails to start (`CreateContainerError` on missing Secret). The spec should list `mclaude-control-plane` (or the value of `controlPlane.existingSecret`) as a pre-requisite with key `admin-token`. |

### GAP 2: `sessions.create` payload in spec-state-schema missing `allowedTools` field

| Field | Value |
|-------|-------|
| **Summary** | The `sessions.create` NATS payload definition in spec-state-schema.md omits `allowedTools`, but both the session-agent code and spec-session-agent.md describe it as part of the request. |
| **Code** | `mclaude-session-agent/agent.go` `handleCreate()` — parses `AllowedTools []string \x60json:"allowedTools"\x60` from the sessions.create payload. When present, builds a set used by `allowlist` and `strict-allowlist` policies. |
| **Spec** | `docs/spec-state-schema.md` § NATS Subjects — `api.sessions.create` payload is listed as: `{name, branch, cwd, joinWorktree, extraFlags, permPolicy, quotaMonitor, requestId}` — no `allowedTools`. Meanwhile, `docs/mclaude-session-agent/spec-session-agent.md` § "Permission Policy" says: "When no explicit allowed-tools list is provided for allowlist or strict-allowlist, a default set is applied" — implying the create request carries the list. |
| **Detail** | The canonical payload schema in spec-state-schema should include `allowedTools` (optional string array). Its absence means the spec-state-schema and spec-session-agent are internally inconsistent, and any implementation relying solely on spec-state-schema for the create payload would miss the field. |

### GAP 3: `subj.go` missing `UserHostProjectAPISessionsRestart` helper — asymmetric with `subj.ts`

| Field | Value |
|-------|-------|
| **Summary** | TypeScript `subj.ts` exports `subjSessionsRestart()` but Go `subj.go` has no corresponding `UserHostProjectAPISessionsRestart()` function. All other session API subject helpers (input, control, create, delete) exist in both files. |
| **Code** | `mclaude-web/src/lib/subj.ts` — exports `subjSessionsRestart(uslug, hslug, pslug)` returning `mclaude.users.{uslug}.hosts.{hslug}.projects.{pslug}.api.sessions.restart`. `mclaude-common/pkg/subj/subj.go` has `UserHostProjectAPISessionsInput`, `UserHostProjectAPISessionsControl`, `UserHostProjectAPISessionsCreate`, `UserHostProjectAPISessionsDelete` but no `…Restart`. |
| **Spec** | `docs/spec-state-schema.md` § NATS Subjects lists `api.sessions.restart` as a valid subject. `docs/mclaude-web/spec-web.md` § TypeScript Slug/Subject Mirrors says `src/lib/subj.ts` "mirrors mclaude-common/pkg/subj." |
| **Detail** | The session-agent works around the missing Go helper by deriving the restart filter subject via prefix manipulation (`prefix + "restart"`), so there is no runtime bug. However, if any future Go code (e.g. a CLI restart command, a test utility) needs this subject, it would have to construct it manually. The asymmetry also contradicts the spec claim that `subj.ts` mirrors `subj.go`. |

## Confidence: **MEDIUM-HIGH**

Three unflagged gaps found. GAP 1 (pre-requisite Secret mismatch) is operationally significant — a fresh Helm install following only the spec would fail because the required `mclaude-control-plane` Secret with `admin-token` key is not created by any chart resource. GAP 2 (missing `allowedTools` in payload schema) is a spec documentation inconsistency that could cause incorrect implementations. GAP 3 (asymmetric subj helpers) is low-severity but contradicts the spec's "mirrors" claim.
