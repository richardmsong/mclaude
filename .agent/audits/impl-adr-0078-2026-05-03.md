**Note on unit test fidelity:** `TestHandleNATSImportRequest_ReplyFieldID` calls `handleNATSImportRequest` with `Reply=""` (so `msg.Respond` is never invoked) and then marshals a *separate* literal `map[string]string{"id": importID, "uploadUrl": uploadURL}` to assert the key. This tests the marshal expression in isolation — it does NOT capture the actual bytes that the handler sends over NATS. The test would still pass even if the production marshal call used a different key, because it re-creates the map itself. This is a fidelity gap in the unit test: it validates the ADR's intent but not the handler's actual output path. The integration tests (which go through the full NATS round-trip) are the real regression guard here. The unit test is better than nothing but weaker than ideal.
